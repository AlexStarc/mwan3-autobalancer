# Калибровка и расход тестового трафика

Автобалансировка распределяет новые соединения по оценкам скорости скачивания. Само применение рассчитанных долей не запускает замер. Основной расход трафика создают активные пробы.

Для нового или переподключённого канала контроллер ждёт 60 секунд стабильности и получает два достоверных результата. Повторные попытки идут с промежутком не менее 120 секунд. На канал допускается до пяти попыток, с ограничением времени и бюджета. Для трёх WAN начальное окно калибровки — 10 минут; для большого числа последовательных проб оно увеличивается.

После калибровки доступны два режима:

| Режим | Активные замеры | Что обнаруживает |
|---|---|---|
| Редкая поддержка (`hybrid`) | По умолчанию раз в 6 часов на канал, а также после его переподключения | Изменение доступности и постепенное изменение скорости |
| Только при изменении (`on-change`) | После калибровки — только при переподключении или смене устройства/адреса канала | Изменение доступности; замедление работающего LTE может остаться незамеченным |

Лёгкая проверка локального состояния продолжается примерно раз в 20 секунд в обоих режимах. Демон и независимый watchdog остаются запущены. Неизменившиеся правила повторно не применяются. Существующие соединения сохраняют свой WAN при изменении только весов.

В режиме `on-change` последние применённые доли удерживаются и после устаревания оценки; UI показывает её возраст. В режиме `hybrid` просроченная оценка возвращается к правилу распределения для неизвестной скорости. Ошибка тестового сервера сама по себе не отключает WAN.

Начальный размер пробы — 32 МиБ. Слишком короткая загрузка не считается достоверной: возможен один повтор с удвоенным объёмом в пределах настроенного потолка и оставшегося бюджета. URL может содержать `{bytes}`, чтобы тестовый сервер отдавал соответствующий объём. Пробы разных WAN выполняются последовательно.

Суточный лимит по умолчанию — 256 МиБ **на каждый логический WAN**. До запроса резервируется его максимальный объём, включая неуспешные запросы и увеличенный повтор. Поэтому показанный расход бюджета может превышать фактическую загрузку. Заголовки и транспортные накладные расходы в него не входят: это не точный счётчик списаний оператора. Записи переживают перезапуск, новые сутки считаются по UTC; перевод часов назад не открывает бюджет заново.

Интервал, объём пробы и дневной лимит можно переопределить для отдельных WAN. При установке включён режим наблюдения, URL пуст: автоматических замеров и применения весов нет. Аварийные команды доступны в [инструкции восстановления](RECOVERY.ru.md).
