# Исправление статистики curl в v0.1.4

7 октября 2026 года выпущен backend `0.1.4-r1`; LuCI остаётся `0.1.3-r1`. Исходники: `e73f572c6b9e71735e567f40231472ddb772514e`, [PR #5](https://github.com/AlexStarc/mwan3-autobalancer/pull/5), [релиз](https://github.com/AlexStarc/mwan3-autobalancer/releases/tag/v0.1.4).

## Причина и исправление

Без HTTP-ответа curl выводит код `000`. Старый шаблон вставлял его в JSON без кавычек, поэтому при сбое передачи пользователь видел ошибку JSON вместо исходной ошибки curl. Контроллер использует штатный `%{json}`: отсутствие ответа представлено числом `0`, строки экранируются самим curl.

Если статистика отсутствует или повреждена, исходная ошибка команды сохраняется вместе с ошибкой разбора. Таймаут может стать измерением только на установленном временном пределе после HTTP 200/206 и получения данных; прежние ограничения объёма, длительности, источника, назначения, поколения и квот продолжают действовать.

URL измерений, настройки WAN/модемов, автоматический режим и правила расчёта долей не изменены. Исправление не устраняет USB-обрывы или недоступность внешнего сервера.

## Проверки

Настоящий curl с отсутствующим локальным файлом воспроизвёл ошибку JSON на старой реализации без сетевого трафика. После исправления статистика разбирается, а исходная ошибка сохраняется. Проверены повреждённая/отсутствующая статистика, таймауты без ответа/данных, другие ошибки curl, HTTP-ошибка, успешные передачи и допустимые замеры с ограничением по времени. Каждая попытка сохраняет списание резерва; проба не пишет правила маршрутизации.

Полные tests/race/vet прошли на Go 1.23.12 и 1.27.1; прошли 23 проверки OpenWrt/recovery, 4 проверки пакетов, EN/RU LuCI и строгая проверка OpenSpec. Независимое ревью не обнаружило блокеров. Все четыре задания [CI](https://github.com/AlexStarc/mwan3-autobalancer/actions/runs/37670585410) прошли, включая настоящую SDK-сборку OpenWrt 24.10.8. Дерево GitHub merge совпадает с проверенным деревом исходников.

## Проверка устройства

Перед установкой выданы команды отключения, удаления и возврата backend 0.1.3; неизменяемый старый IPK сохранён на роутере. Установлен только backend 0.1.4 на том же ZBT Z8102AX/OpenWrt 24.10.8/mwan3 2.11.16-r5/IPv4 iptables-legacy.

Проверены SHA256 архива CI, обоих IPK и статический AArch64 ELF без динамического загрузчика. В backend изменился только бинарник: остальные 13 файлов и все 5 файлов LuCI совпадают с предыдущими пакетами. Все 12 устанавливаемых runtime-файлов backend совпали с SDK; сохранённые настройки и бюджеты проверены отдельно.

После обновления сохранены настройки контроллера, mwan3, network и LuCI, квоты, история измерений, расписание и старые диагностические сообщения. Подтверждены настоящий watchdog, lease и heartbeat текущего владельца, доступность автоматического применения и отсутствие изменения всех 110 правил IPv4/IPv6.

Один обычный запрос измерений через очередь контроллера успешно проверил три активных WAN. На 22:24:25 МСК `modem1`, `modem2` и `petra` имеют состояние `measured`, пустые ошибки и ровно одну новую валидную попытку. Для каждого зарезервировано ровно 32 МиБ; увеличенных повторных загрузок не было. Отключённый `wan` не измерялся. Резерв не является счётчиком фактически переданных байтов.

У Petra появился первый валидный замер. До второго замера существующая проверка достоверности скрывает оценку скорости; LuCI показывает неизвестную оценку без ошибки. Старые доли 44,8% / 21,9% / 33,3% сохранились; история двух остальных каналов продолжена. В настоящем русском LuCI подтверждены периодическое расписание, доступность автоматического применения и отсутствие прежних ошибок JSON.

В проверочном цикле сервер Cloudflare оказался доступен со всех трёх WAN. Это не доказывает, что исправление JSON устранило прежние сетевые таймауты. Сохранение исходных ошибок при отсутствующем HTTP-ответе доказано регрессионными тестами; новая форма JSON дополнительно проверена на curl самого роутера без сетевого трафика. Не создавались искусственные отключения WAN или USB.
