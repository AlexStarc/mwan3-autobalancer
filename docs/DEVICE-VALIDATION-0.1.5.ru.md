Дата проверки: 11 ноября 2026 года. Целевая платформа: ZBT Z8102AX, OpenWrt 24.10.8, mwan3 2.11.16-r5, IPv4 iptables-legacy, ARM64 Cortex-A53.

Проверяемый код: `4ae260ac5f53c6848baba67bfe4ca650fcf7cc17`, PR [#6](https://github.com/AlexStarc/mwan3-autobalancer/pull/6). Все четыре задания [CI](https://github.com/AlexStarc/mwan3-autobalancer/actions/runs/42970783284) завершились успешно: полные тесты/race/vet Go 1.23.12 и 1.27.1, проверки OpenWrt/UI и настоящая сборка пакетов в SDK.

## Особенности, обнаруженные на устройстве

`mwan3 use` печатает служебную строку в stdout. Аргумент curl `--write-out` может добавлять в неё переводы строк. Поэтому тело ответа API записывается в отдельный приватный временный файл, а статистика curl разбирается отдельно. Чтение ограничено 64 КиБ + один байт для обнаружения превышения; временный файл удаляется после попытки. Регрессионный тест воспроизводит реальный многострочный вывод.

Два выделенных тестовых узла из ответа API не установили соединение через `modem1` за четыре секунды. Резервный сервисный адрес, возвращённый тем же API, ответил HTTP 206 и отдал ровно 1024 запрошенных байта за 1.37 секунды. Поэтому при наличии валидного `fallbackUrl` используется он. Если резервный адрес отсутствует или не проходит проверку, допускается валидный основной URL. Сам адрес и параметры запроса получаются из API.

## Небольшая проверка до установки

На роутере выполнен временный диагностический запуск проверенного кода `Adapter.Probe`, собранного Go 1.27.1 для Linux ARM64 без динамического загрузчика. Диагностический запуск не вызывает применение правил и не заменяет установленную службу. Для него использовался отдельный каталог кеша; постоянный бюджет резервировался штатным механизмом.

| Канал | Получение адреса | Ограниченная загрузка |
|---|---|---|
| modem1 / wwan0 | Успешно | 256 КиБ, HTTP и источник проверены |
| modem2 / wwan1 | Успешно | 256 КиБ, HTTP и источник проверены |
| petra / eth2 | Успешно | 256 КиБ, HTTP и источник проверены |

Все три загрузки корректно отклонены как слишком короткие для оценки скорости: критерий достоверности не снижался. Проверка подтверждает получение и разбор адресов, привязку запроса и работу загрузки, но не измеряет пропускную способность.

Кеши содержали разные идентификаторы запросов API для WAN, нулевые счётчики ошибок и имели права `0600`; каталог — `0700`. Временных файлов тела ответа после завершения не осталось. Диагностические файлы и программа удалены с устройства. Хеши конфигураций network, wireless и mwan3 совпали с исходными.

## Обычные измерения и кеш

Установленная служба сама получила три адреса из API. На каждый WAN первый цикл зарезервировал ровно 32 МиБ загрузки и 64 КиБ метаданных. В последующих циклах адреса и времена получения/попытки оставались прежними; повторная резервация на modem1 и modem2 составила ровно 32 МиБ без дополнительных 64 КиБ. Кеш Petra сохранился при переподключении USB. Каталог имеет права `0700`, кеши — `0600`; временные файлы тела ответа удалены.

На каждом из трёх каналов зарегистрирован успешный обычный замер. Устойчивую калибровку всех трёх каналов одновременно подтвердить не удалось: в журнале есть USB-отключения Petra до обновления (09:31) и после него (09:35–09:39). Это сбрасывает её калибровку; изменение общей генерации также приводит к безопасному отбрасыванию некоторых измерений других WAN, идущих в этот момент. Такие результаты не увеличили счётчики ошибок CDN и не вызвали повторного получения адреса.

Контроллер и независимый watchdog работали, `apply_ready=true`, `last_error` пуст. Когда Petra уходила offline, её применённый вес был нулевым. Испытания не доказывают длительную стабильность USB и не заменяют отдельную проверку питания/соединения Petra.

## Ограничения

API Интернетометра не документирован и может измениться. Автоматическое получение поддерживает совместимые изменения CDN-адресов и не гарантирует неизменность API. Недоступность тестового узла не доказывает недоступность WAN. Повторные USB-переподключения Petra этим изменением не исправляются.
