# Approved design

Each logical interface has a persisted measurement throttle separate from its epoch-bound samples and calibration schedule. Online transitions still invalidate samples. Automatic probes require at least five minutes of continuously observed online state and fifteen minutes since the previous actual measurement. Configured longer settle/calibration intervals remain effective. A restart conservatively re-arms settling because continuity during downtime is unknown.

Reserve and persist the throttle immediately before the first payload curl, after discovery, route checks and quota reservation. Build private candidate schedule/throttle maps under the engine mutex, persist them, and publish the counters and report only on success. A persistence refusal consumes no measurement attempt, failure streak or throttle deadline; conservative budget reservations are retained. Treat the existing one larger-payload confidence retry as part of that bounded measurement attempt. Discovery deferrals, failed discovery, route checks and quota refusals do not increment measurement attempts or failures.

Failed measurements retry after 15, 30, then 60 minutes, capped at 60. Success resets consecutive failures. Completed successful calibration retains the configured maintenance interval (the deployed four-hour setting); failure in maintenance uses failure backoff. Reconnect retains throttling and failure streak but starts fresh finite calibration. Five actual calibration attempts remain the limit, with a window large enough for settle, serial probes, and worst-case failure delays. After exhaustion, on-change holds and hybrid waits its configured maintenance interval; retry backoff does not create an unlimited calibration loop. Discovery deferrals extend the window enough to leave time for real measurements.

Manual probing explicitly bypasses automatic waiting guards, still enforces online/transport/quota checks, and records actual attempts and outcomes for subsequent automatic scheduling. Reporting uses the same effective next deadline as execution. Existing state without throttle fields loads safely. No routing/leaf-conflict behavior changes.

Validation: deterministic fixtures cover stable online, repeated flaps, generation changes, independent channels, 15/30/60 failures, success reset, restart/in-flight persistence, manual behavior, discovery and finite calibration; run all Go/race/vet and OpenWrt/package/UI fixtures.

Continuously online means observed through normal polling; disconnects entirely between checks may be missed. Runtime state survives daemon/service restarts on the current helpers, but /var/run is volatile across router reboot. Legacy schedules without throttle records receive a conservative 15-minute migration quarantine.
